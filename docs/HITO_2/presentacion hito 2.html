01 · Introducción y evolución

Consolidar la base técnica sin perder el foco.

PRIVACYOS transforma señales observables de privacidad en informes con hallazgos, puntajes y recomendaciones explicables. En este hito evolucionamos la arquitectura sin confundir capacidades actuales con propuestas futuras.

BASE · HITO 1

Prototipo web responsivo

  • Consultaba una página pública mediante análisis acotado.
  • Endpoint aislado POST /api/analyze sin persistencia en servidor.
  • Almacenamiento de historial exclusivamente en el navegador (localStorage).
Evolución · Hito 2

Arquitectura REST y relacional

  • API REST completa para gestionar sitios y análisis ejecutados.
  • Persistencia relacional en PostgreSQL (Supabase) mediante Prisma 6.
  • Separación explícita entre rutas HTTP, contratos, servicios y repositorios.
Alcance explícito: cuentas, autenticación, crawling exhaustivo, comparación textual de políticas y monitorización continua no forman parte de este hito y no se presentan como entregadas.

04 · Contratos, errores y pruebas

Respuestas predecibles y control de fallos.

Crear análisis · POST /api/analyses

// Request JSON { "url": "https://www.chile.gob.cl", "frameworkIds": ["CL-19628", "CL-21719", "GDPR"] } // Respuesta HTTP 201: objeto persistido con ID PS-XXXXXX, score y resultados

Actualizar revisión · PATCH /api/analyses/{id}

{ "notas": "priorizar hallazgo 2", "revisado": true }

Semántica de errores y versionado

// Envolvente uniforme de error { "ok": false, "code": "VALIDACION", "message": "..." }

Códigos controlados: 409 URL duplicada o sitio con análisis; 404 recurso ausente; 403 bloqueo anti-SSRF; 504 tiempo máximo excedido.

Versionado: prefijo actual /api; el contrato establece introducir /api/v1 ante cambios incompatibles o consumidores externos.

Verificación documentada: colección docs/privacyos-hito2.postman_collection.json y script scripts/test-crud.mjs (21 verificaciones descritas en repositorio).

05 · Separación de responsabilidades

Un monolito modular con límites claros.

Esta estructura evita que la vista realice consultas SQL o que los controladores HTTP concentren lógica de negocio.

components/ y app/Capa de presentación y navegación de la interfaz web.
lib/api-client.tsCliente de consumo de API y degradación explícita a localStorage.
app/api/sites y analysesRoute handlers: reciben el método HTTP, validan entradas y serializan respuestas.
lib/contracts.ts & lib/httpContratos Zod compartidos (URL, IDs, cuerpos) y normalización de errores HTTP.
lib/services/Reglas de negocio, coordinación del análisis y generación del ID PS-XXXXXX.
lib/analyzer/Motor de observación limitada del sitio, guardas de seguridad anti-SSRF, hallazgos y score.
lib/repositories/ & lib/dbOperaciones de lectura/escritura y cliente Prisma reutilizable conectado a PostgreSQL.
prisma/, db/, scripts/Esquema, migraciones, script SQL reproducible, pruebas y documentación.
06 · Recorrido completo: POST /api/analyses

Ciclo de vida de un análisis persistido.

01
Solicitud UI

La interfaz envía la URL objetivo y los marcos normativos seleccionados.

02
Validación Zod

El route handler verifica la estructura del cuerpo JSON mediante contratos Zod.

03
Coordinación

El servicio orquesta la ejecución y genera un identificador único PS-XXXXXX.

04
Motor y SSRF

Valida protocolo, puertos, DNS y redirecciones; inspecciona HTML, headers y cookies.

05
Persistencia

El repositorio usa Prisma para guardar score, riskLevel y payload JSONB en PostgreSQL.

06
Respuesta 201

El servicio devuelve el resultado estructurado y el handler responde HTTP 201.

07
Presentación

La UI despliega el informe; ante indisponibilidad de API guarda respaldo local explícito.

✓
Trazabilidad

Cada hallazgo queda respaldado en base de datos y listo para consulta o revisión posterior.

07 · Persistencia y modelo relacional

Esquema híbrido: integridad relacional + JSONB.

Definido en prisma/schema.prisma y reproducible vía migración 20261026000000_init o db/init.sql.

Tabla: sites

Entidad Padre · 1:N

Columnas definidas:

PK id UNIQUE url nombre notas fechas auditoría
Índice y regla de integridad sites_url_key garantiza URL única. Con ON DELETE RESTRICT, un sitio con análisis asociados no se puede eliminar directamente.

Tabla: analyses

Entidad Hija · Resultados

Columnas definidas:

PK id url score (int) riskLevel JSONB payload notas revisado (bool) FK siteId (opc.) fechas
Índices y almacenamiento flexible analyses_createdAt_idx (orden cronológico) y analyses_siteId_idx (filtro por sitio). JSONB conserva el informe completo sin proliferar tablas.
08 · Reproducción de BD y gestión de credenciales

Entorno reproducible y manejo seguro de secretos.

Reproducción de base de datos
  1. Preparar una instancia PostgreSQL accesible (Supabase).
  2. Configurar DATABASE_URL en .env.local sin publicar secretos.
  3. Ejecutar npm install y npx prisma generate.
  4. Aplicar npx prisma migrate deploy o ejecutar db/init.sql.
  5. Iniciar la app en localhost:3000 y verificar con scripts/test-crud.mjs.
SEGURIDAD Y VARIABLES DE ENTORNO
  • .env.example documenta nombres de variables; .gitignore excluye archivos locales.
  • DATABASE_URL se inyecta vía Vercel o .env.local.
  • GEMINI_API_KEY opera exclusivamente en servidor; ASSISTANT_ENABLED condiciona el asistente.
  • Regla estricta: nunca exponer tokens ni cadenas reales en repositorios o informes. La autenticación queda fuera del alcance de este hito.
